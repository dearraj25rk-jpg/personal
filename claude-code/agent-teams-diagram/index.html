Pattern 2: Parallel Fan-Out

Section titled “Pattern 2: Parallel Fan-Out”

Orchestrator splits a large task into independent subtasks and runs all concurrently. Results are collected and merged.

Key constraint: Independent subtasks only. If svc-b depends on svc-a’s output, use Sequential Pipeline or Staged Fan-Out (Pattern 4) instead.

Pattern 3: Specialist Pool

Section titled “Pattern 3: Specialist Pool”

A fixed set of domain-expert agents handle requests routed to them by an orchestrator. Each specialist is persistent and accumulates domain context.

Advantage over Task Tool: Each specialist retains memory of prior tasks in the session, so the backend specialist “knows” what APIs were added last hour without re-reading the codebase.

Pattern 4: Staged Fan-Out (Hybrid)

Section titled “Pattern 4: Staged Fan-Out (Hybrid)”

Combines sequential stages with parallel execution within each stage. Most powerful pattern for large codebases.

This is the recommended pattern for large feature work (> 500 lines of change) as it maximises parallelism while respecting dependencies.

Pattern 5: Peer Review Loop

Section titled “Pattern 5: Peer Review Loop”

Two agents review each other’s work iteratively until both agree the output meets quality criteria. Useful for high-stakes code that needs adversarial review.

Loop termination conditions:

  • Reviewer sends result with approved: true
  • Loop count reaches max_review_cycles (set in team.json)
  • Any agent sends error with recoverable: false
