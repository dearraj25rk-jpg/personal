What is Context Engineering?

Section titled “What is Context Engineering?”

Context engineering (CE) is the practice of deliberately managing what information enters Claude’s context window on each API call, and when. Unlike prompt engineering (which focuses on how you phrase instructions), CE focuses on what is present in the context at each turn — and at what cost.

Every token in Claude’s context window costs money on every API call. A context window with 800K used tokens costs roughly 4× as much per turn as one with 200K used tokens, even for the same user prompt. CE is the discipline of maximising signal while minimising token cost.

ToolSearch Lazy Loading (v2.1.7+)

Section titled “ToolSearch Lazy Loading (v2.1.7+)”

Deferred tools only load their full schema when first used in a session. Built-in tools stay eager (always loaded). This saves 60–80% of tool schema overhead for most sessions with no configuration required.

Tool categoryLoadingToken cost per tool
Built-in core (Read, Edit, Bash…)Eager~2,900/tool (always)
WebSearch, WebFetch, ToolSearchDeferred~80 name+desc until used
MCP tool schemasPer-connection~2,650/server (fixed)

Check deferred tool state with /context — look for the “deferred tools” line.

MEMORY.md — Durable Auto-Memory

Section titled “MEMORY.md — Durable Auto-Memory”

MEMORY.md is Claude Code’s durable per-project memory file. Unlike CLAUDE.md, it is:

  • Written automatically by Claude during sessions (via /memory add)
  • Reloaded fully after every compaction (not summarised away)
  • Stored at ~/.claude/projects/<hash>/memory/MEMORY.md
  • Limited to 200 lines / 25KB

Use /memory to view and edit. Add project-specific facts that should persist across all sessions: database schemas, API quirks, known bugs, architectural decisions already made.

What belongs in MEMORY.md vs CLAUDE.md:

MEMORY.mdCLAUDE.md
Discoveries made during sessionsStanding project conventions
”We decided to use JWT not sessions""Always use JWT for auth”
Current task state, blockersTeam conventions and standards
Per-session notesArchitectural decisions (permanent)
Automatically written by ClaudeManually maintained by team

/advisor — CE Superpower

Section titled “/advisor — CE Superpower”

/advisor activates dual-model mode: Sonnet 4.6 handles execution (reading files, running tools, writing code) while Opus 4.7 reviews context periodically and provides strategic guidance.

ModeCost per sessionBest for
Sonnet only~$5–15Standard feature work
/advisor~$20–45Architecture, ambiguous bugs
Opus only~$50–150Highest complexity, slowest

Activate: /advisor · Force immediate: /advisor now · Deactivate: /advisor off

Auto-Compaction Mechanics

Section titled “Auto-Compaction Mechanics”

Compaction fires at 83.5% context used (~835K of 1M, ~167K of 200K).
Each compaction costs 100–200K tokens to execute. Run /compact proactively at 70%.

Survives compactionDiscarded by compaction
Project-root CLAUDE.md (reloaded from disk)Redundant tool results
MEMORY.md (fully reloaded, not summarised)Path-scoped CLAUDE.md (auto-reloads on next file touch)
Architectural decisions (summarised)Old conversation turns
5 most-recently-accessed filesRaw bash outputs from completed tasks
Skills (re-injected up to cap)Thinking token traces from prior turns
NOTES.md / TODO.md if Claude re-reads themRepeated messages

CE Anti-Patterns to Avoid

Section titled “CE Anti-Patterns to Avoid”
Anti-patternProblemCE fix
Starting every session by asking Claude to “read the entire codebase”50-200K tokens wasted on context that won’t all be relevantUse Glob/Grep to SELECT specific files; let rules inject context conditionally
Giant CLAUDE.md with 500+ linesEvery session pays full cost; most content irrelevant to current taskSplit into path-scoped rules; keep root CLAUDE.md under 200 lines
Never running /compactContext degrades at 85%+; compaction is more expensive than proactive compactRun /compact at 70% with a focus instruction
One giant session for unrelated tasksContext from task A pollutes task B; costs compoundUse /clear between unrelated tasks; ISOLATE with separate sessions
Asking Claude to remember things verballyVerbal “remember this” has no persistenceWRITE to MEMORY.md or CLAUDE.md explicitly
Running 10 MCP servers for every project26,500 extra tokens every sessionConnect only servers needed for current task via .claude/.mcp.json.local
