Security Hardening Checklist

Section titled “Security Hardening Checklist”

  • Use bypassPermissions only in sandboxed CI environment
  • Set --max-budget-usd to cap runaway costs
  • Audit hooks log all tool calls
  • Pin anthropics/claude-code-action@v1 (use SHA pin in production)
  • Restrict allowedTools to what CI needs

Security Hardening Checklist

Section titled “Security Hardening Checklist”
CheckWhy it mattersHow to implement
Pin actions to commit SHAPrevents supply-chain attacks from tag mutationuses: actions/checkout@a5ac7e51b41094c92402da3b24376905139b6c84 instead of @v4
Use OIDC instead of long-lived secretsEliminates key rotation risk; tokens expire in minutesGitHub → AWS: aws-actions/configure-aws-credentials with role-to-assume; GCP: WIF provider
Set --max-budget-usdPrevents runaway cost if prompt loopsmax_budget_usd: "3.00" — match to task complexity
Use --bare modeSkips non-essential steps; reduces attack surfaceclaude_code_flags: "--bare"
Restrict to bypassPermissions only for trusted reposUntrusted forks should not auto-accept file writesAdd if: github.event.pull_request.head.repo.full_name == github.repository
Scope allowed_toolsPrinciple of least privilegePR review needs only Read,Bash(git*) — never grant Write for review-only jobs
Rotate API keys quarterlyLimits blast radius of leaked keysUse GitHub secret rotation; prefer OIDC to eliminate keys entirely
Enable concurrency controlsPrevents parallel CI runs from double-postingconcurrency: group: ${{ github.workflow }}-${{ github.ref }}
Audit tool call logsDetect unexpected tool use in CIEnable PostBash hook to log all shell commands
Sandbox CI runnersPrevent lateral movement if compromisedUse ephemeral ubuntu-latest runners; avoid self-hosted for untrusted code
