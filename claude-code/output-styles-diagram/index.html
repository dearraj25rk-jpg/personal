Output Styles Quick Reference

Section titled “Output Styles Quick Reference”

Claude Code ships with three built-in output styles. Each replaces the SE-specific system prompt block (see below) while optionally preserving or discarding the software-engineering behavioral instructions.

StyleTonekeep-coding-instructions defaultBest forToken cost vs. Default
DefaultConcise, direct, tool-focusedN/A (baseline)Day-to-day coding, CI, agentic loopsBaseline
ExplanatoryVerbose, step-by-step reasoningtrueOnboarding, pair-review, understanding unfamiliar code+15–30% output tokens
LearningSocratic, question-driven, educationaltrueSkill-building, juniors, code walkthroughs+20–40% output tokens

Version note: Output Styles were introduced in v2.0.64. The keep-coding-instructions key and custom style YAML format reached stable API in v2.1.0. All three built-in styles ship with v2.1.126.

What Gets Replaced

Section titled “What Gets Replaced”

Every Claude Code session begins with a system prompt composed of several blocks. One of those blocks is the SE (Software Engineering) block — a large section that contains:

  • File-tool preference instructions (use Read/Edit/Grep instead of cat/sed/grep)
  • Git workflow guidance (conventional commits, branch hygiene)
  • Test-driven development heuristics
  • Safety rules (no rm -rf without confirmation, no git push --force to main)
  • Code style defaults (language-idiomatic, minimal comments, no emojis)

When you activate an output style, the SE block is replaced with the style’s own system prompt text. The rest of the system prompt (session metadata, tool definitions, permissions block, CLAUDE.md contents) is not touched.

This means:

  • Your CLAUDE.md instructions are always preserved regardless of style.
  • Your .claude/settings.json permission rules still apply.
  • Only the style of response and the embedded behavioral defaults change.

keep-coding-instructions Behavior

Section titled “keep-coding-instructions Behavior”

The keep-coding-instructions flag in a custom style (or surfaced via the built-in style config) controls whether the SE behavioral block is appended after the style’s own prompt text rather than discarded.

keep-coding-instructions: false (default for custom styles)

Section titled “keep-coding-instructions: false (default for custom styles)”

The SE block is fully replaced. You lose:

  • Tool preference reminders (Read over cat, etc.)
  • Git safety rules (no force-push warnings)
  • TDD heuristics
  • Code style defaults

You keep everything in your CLAUDE.md, settings.json, and path-scoped rules.

Use when: Your custom style already encodes all the behavioral instructions you need, or you want a clean slate (e.g., a non-coding writing style for documentation work).

keep-coding-instructions: true

Section titled “keep-coding-instructions: true”

The style’s prompt text is prepended to the SE block. Claude gets both the style tone guidance and the full SE behavioral instructions. This is the setting used by both Explanatory and Learning built-in styles.

What you keep:

  • All SE safety rules and tool-use preferences
  • All style-specific tone and structure guidance

What you lose:

  • Nothing — this is the union of both prompt blocks

Activation Methods

Section titled “Activation Methods”

1. Interactive: /config command

Section titled “1. Interactive: /config command”

Changes take effect immediately for the current session and persist to your local settings.

2. defaultStyle in settings.json

Section titled “2. defaultStyle in settings.json”

Set a permanent default in your project or user settings:

The value is the name field from the style YAML, or one of the three built-in names: "Default", "Explanatory", "Learning".

3. CLI flag (session override)

Section titled “3. CLI flag (session override)”

The --style flag overrides defaultStyle for that session only.

4. Team distribution via shared settings

Section titled “4. Team distribution via shared settings”

In a monorepo, commit a .claude/styles/ directory with your team styles and a .claude/settings.json that sets defaultStyle. Every engineer who clones the repo gets the same baseline style.

When to Use Each Style

Section titled “When to Use Each Style”
SituationRecommended styleReason
Regular feature developmentDefaultLowest token cost, fastest iteration
CI / agentic pipelinesDefaultOutput is parsed, not read — verbosity is waste
Onboarding a new codebaseExplanatoryStep-by-step reasoning helps you learn the territory
Code review with a juniorExplanatoryVerbose rationale teaches, not just fixes
Learning a new language/frameworkLearningSocratic questions build mental models
Documentation writingCustom (no keep-coding)Clean prose style, SE defaults are irrelevant
Incident responseCustom (keep-coding: true)Terse voice but full SE safety rules still apply
PR review workflowCustom (keep-coding: true)Structured review format + SE code judgment

Token Cost Implications

Section titled “Token Cost Implications”

Output styles affect both input tokens (the system prompt) and output tokens (response verbosity).

Input token impact (system prompt size)

Section titled “Input token impact (system prompt size)”
StyleApproximate system prompt delta
DefaultBaseline (0)
Explanatory+800–1,200 tokens (SE block preserved + style preamble)
Learning+900–1,300 tokens (SE block preserved + Socratic preamble)
Custom (keep-coding: false)−2,000–4,000 tokens (SE block removed; your style text replaces it)
Custom (keep-coding: true)+200–800 tokens (your style text prepended to SE block)

Exact numbers vary with Claude Code version. The SE block grows as new behavioral guidance is added.

Cost optimisation tips

Section titled “Cost optimisation tips”
  • Use Explanatory only for interactive sessions where you will read every word.
  • A custom terse style (e.g., keep-coding: false + short system prompt) is the cheapest option for high-volume agentic workloads — cheaper than Default because the SE block is removed.
  • Learning style is expensive in long sessions; switch back to Default once you understand the domain.
  • Monitor actual costs with /usage before and after switching styles to calibrate for your workload.
