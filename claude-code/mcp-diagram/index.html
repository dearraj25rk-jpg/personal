Tool Description Best Practices

Section titled “Tool Description Best Practices”

Good tool descriptions reduce Claude’s token usage and improve accuracy:

PatternExample
Action verb + noun"Get customer order history by customer ID"
Include constraints"Max 100 results. Returns null if not found."
Mention side effects"WRITES to database. Irreversible."
Expected input format"Date in ISO 8601 format: YYYY-MM-DD"

Keep descriptions under 100 tokens — each tool schema costs tokens. A server with 20 tools costs ~2,650 tokens regardless of description length.

Security Checklist for MCP Servers

Section titled “Security Checklist for MCP Servers”
  • Validate all inputs with a schema library (Zod, Pydantic)
  • Never expose destructive operations (DROP TABLE) without confirmation
  • Use readonly: true flag for read-only tools to signal intent
  • Scope database users to minimum required permissions
  • Audit log all MCP tool calls via PostMCPTool hook
  • Use CLAUDE_CODE_DISABLE_MCP_TOOLS to blocklist dangerous tools
  • Rotate credentials; use environment variables never hardcoded in .mcp.json

MCP uses JSON-RPC 2.0 as its wire format. All messages are newline-delimited JSON objects sent over the chosen transport. There are four message types: requests, responses, notifications, and errors.

stdio vs HTTP — When to Use Each

Section titled “stdio vs HTTP — When to Use Each”

Decision guide:

ScenarioTransportReason
Local CLI tool wrapping your databasestdioSimple, no network exposure
Shared team server running in KuberneteshttpCentral, accessible to all devs
Sandboxed tool in CI environmentstdioProcess isolation, no open ports
SaaS MCP provider (e.g. Browserbase)httpExternal network required
Dev-only personal scriptsstdioZero configuration
Multi-tenant enterprise deploymenthttpOne server → many users

Latency Characteristics

Section titled “Latency Characteristics”

Rule of thumb: For interactive Claude Code sessions, keep round-trip tool calls under 500ms. Remote HTTP servers with high latency will noticeably slow down sessions.

12 Official MCP Servers

Section titled “12 Official MCP Servers”

Complete configuration examples for each official server. Install via npm or npx.

1. filesystem

Section titled “1. filesystem”

Read, write, move, and search files within allowed directories.

Key tools: read_file, write_file, list_directory, search_files, move_file, create_directory, get_file_info

2. github

Section titled “2. github”

Interact with GitHub repositories, issues, PRs, and code.

Key tools: create_or_update_file, search_repositories, create_repository, get_file_contents, push_files, create_issue, create_pull_request, search_code

3. postgres

Section titled “3. postgres”

Query and inspect PostgreSQL databases.

Key tools: query (read-only SELECT), list_tables, describe_table
Note: Server enforces read-only access by default — no INSERT/UPDATE/DELETE.

4. sqlite

Section titled “4. sqlite”

Query and manage SQLite databases.

Key tools: read_query, write_query, create_table, list_tables, describe_table, append_insight

5. brave-search

Section titled “5. brave-search”

Web search via Brave Search API.

Key tools: brave_web_search (10 results/call), brave_local_search (location-aware)

6. fetch

Section titled “6. fetch”

HTTP fetch for any URL — useful for reading API docs, web pages, or REST endpoints.

Key tools: fetch (GET any URL, returns markdown-converted HTML), fetch_raw (raw content)

7. memory

Section titled “7. memory”

Persistent key-value knowledge graph with semantic search.

Key tools: create_entities, create_relations, add_observations, search_nodes, read_graph, delete_entities

8. puppeteer

Section titled “8. puppeteer”

Browser automation — screenshot, click, type, navigate.

Key tools: puppeteer_navigate, puppeteer_screenshot, puppeteer_click, puppeteer_fill, puppeteer_evaluate, puppeteer_select

9. slack

Section titled “9. slack”

Read channels, post messages, manage Slack workspace.

Key tools: slack_list_channels, slack_post_message, slack_reply_to_thread, slack_get_channel_history, slack_search_messages, slack_get_users

10. google-maps

Section titled “10. google-maps”

Geocoding, place search, directions, and distance matrix.

Key tools: maps_geocode, maps_reverse_geocode, maps_search_places, maps_get_directions, maps_distance_matrix, maps_elevation

11. sentry

Section titled “11. sentry”

Read and triage Sentry error reports and issues.

Key tools: get_sentry_issue, list_sentry_issues, get_sentry_event, resolve_sentry_issue

12. sequential-thinking

Section titled “12. sequential-thinking”

Structured multi-step reasoning — forces Claude to break complex problems into explicit steps.

Key tools: sequentialthinking — accepts a problem, returns structured step-by-step analysis. No external API key required.
