Section titled “Usage reporting”

Claude Code emits a usage event at session end containing:

FieldDescription
input_tokensTokens sent to the model this session
output_tokensTokens received from the model
cache_read_tokensTokens served from prompt cache (lower cost)
cache_write_tokensTokens written to prompt cache
estimated_cost_usdCalculated cost at current model pricing
modelModel ID used
session_duration_sWall-clock seconds

These fields are included in every audit log event when auditLogDestination is set.

Phased Organizational Rollout Playbook

Section titled “Phased Organizational Rollout Playbook”

Phase 1 — Pilot (Week 1–2)

Section titled “Phase 1 — Pilot (Week 1–2)”
  1. Select 5–10 volunteer developers from one team
  2. Deploy Claude Code with direct ANTHROPIC_API_KEY (no MDM yet)
  3. Set auditLogDestination to a shared file or Slack webhook for visibility
  4. Collect feedback: which tools are blocked too aggressively, which are too permissive
  5. Document first-pass allow/deny rules for the project .claude/settings.json
  6. Identify which MCP servers the team needs

Phase 2 — Team Rollout (Week 3–4)

Section titled “Phase 2 — Team Rollout (Week 3–4)”
  1. Migrate auth to AWS Bedrock or GCP Vertex (remove individual API keys)
  2. Push first MDM profile with ANTHROPIC_BASE_URL, DISABLE_TELEMETRY, ANTHROPIC_MODEL
  3. Commit .claude/settings.json to the team’s main repository
  4. Run a 1-hour onboarding session using /team-onboarding
  5. Set up SIEM/OTEL audit pipeline from auditLogDestination
  6. Define cost budget via costGovernance block

Phase 3 — Department Rollout (Week 5–8)

Section titled “Phase 3 — Department Rollout (Week 5–8)”
  1. Expand MDM profile to all department devices
  2. Enable allowManagedHooksOnly to restrict hook surface
  3. Configure disableBypassPermissionsMode: true for all non-CI machines
  4. Per-service .claude/settings.json files committed for each repo
  5. MCP server allowlist (allowedMcpServers) locked down in managed-settings
  6. Run cost governance review — adjust per-team budgets

Phase 4 — Org-wide (Week 9–12)

Section titled “Phase 4 — Org-wide (Week 9–12)”
  1. Full MDM rollout across all engineer devices
  2. Centralized audit dashboard connected to SIEM (Splunk/Datadog/etc.)
  3. Fine-grained allow/deny rules per repository type (frontend, backend, infra)
  4. Automated compliance scanning of .claude/settings.json via CI lint step
  5. Quarterly review process: audit logs → rule refinement → MDM profile update
  6. Runbook published internally: how to request a new MCP server, how to appeal a blocked tool

Security Hardening Checklist

Section titled “Security Hardening Checklist”

MDM / Managed Settings

Section titled “MDM / Managed Settings”
  • DISABLE_TELEMETRY=1 set in managed-settings for regulated environments
  • DISABLE_UPDATES=1 set — version pinned and tested before fleet rollout
  • ANTHROPIC_BASE_URL routes through DLP-inspected corporate proxy
  • allowedMcpServers allowlist set — no arbitrary MCP connections
  • auditLogDestination points to SIEM or append-only log target
  • allowManagedHooksOnly: true — prevents user-defined hook scripts

Authentication

Section titled “Authentication”
  • No developer has a personal ANTHROPIC_API_KEY on managed devices
  • Bedrock: IAM roles scoped to Claude models only (bedrock:InvokeModel on specific ARNs)
  • Vertex: Workload Identity Federation configured — no service account JSON files
  • API key rotation policy defined (if using Direct API for any use case)
  • Key stored in secrets manager (AWS Secrets Manager / GCP Secret Manager / HashiCorp Vault), not env files

Network

Section titled “Network”
  • Egress firewall rule: only api.anthropic.com (or your Bedrock/Vertex endpoints) allowed
  • TLS inspection enabled on corporate proxy for AI traffic classification
  • HTTP_PROXY / HTTPS_PROXY set in managed-settings so no traffic bypasses proxy
  • WebFetch tool blocked via deny: ["WebFetch"] unless explicitly needed

Permissions

Section titled “Permissions”
  • disableBypassPermissionsMode: true on all developer machines
  • bypassPermissions mode enabled only in sandboxed CI containers
  • Bash(rm:-rf*) and Bash(git push --force*) in global deny list
  • Read(**/.env*) in deny list — prevents reading secrets files
  • Per-repo .claude/settings.json committed and reviewed in code review

Hooks

Section titled “Hooks”
  • All pre/post-tool hooks reviewed and version-controlled
  • Hook scripts lint-checked in CI (no network calls, no exfiltration patterns)
  • allowManagedHooksOnly set in managed-settings if hook scripts are sensitive
  • Hook outputs logged to auditLogDestination
