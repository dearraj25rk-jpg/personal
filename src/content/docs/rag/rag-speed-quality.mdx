Every RAG system makes an explicit or implicit choice on the speed–quality curve. This interactive guide maps all major retrieval strategies to their latency, accuracy, and infrastructure cost — so you can make that trade-off intentionally.

## The Speed–Quality Curve

```
Quality (NDCG@10)
  ▲
  │                                         ● Cross-encoder Reranking
  │                                   ● ColBERT Late Interaction
  │                             ● Hybrid (dense + BM25) + Reranking
  │                       ● Hybrid (dense + BM25)
  │                 ● Dense-only (HNSW)
  │           ● BM25
  │     ● TF-IDF
  └──────────────────────────────────────────────────────────────▶ Latency
     1ms   5ms  10ms  20ms  50ms  100ms 200ms 500ms  1s
```

## Decision Guidance

**Latency < 10ms required:** BM25 only. Accept lower accuracy or pre-retrieve offline.

**Latency 10–50ms, accuracy important:** Dense HNSW or Hybrid RRF. Good balance.

**Latency 50–200ms, high accuracy:** Hybrid + FlashRank or ColBERT PLAID. Production sweet spot for most systems.

**Latency > 200ms acceptable, maximum accuracy:** Hybrid + full cross-encoder reranking. Best for legal, medical, financial domains where errors are costly.

**Budget constrained, no GPU:** BM25 + dense with CPU HNSW. Self-host with Qdrant or pgvector.

## Pipeline Optimization Patterns

```
PATTERN 1: Recall-then-Precision (recommended)
─────────────────────────────────────────────────
BM25 + Dense → retrieve top-100 (fast, 8ms)
    │
    ▼
FlashRank/Cross-encoder → rerank to top-5 (accurate, +80ms)
    │
    ▼
LLM generation (500–1500ms)

Why: LLM latency dominates anyway; reranking adds <10% to total

PATTERN 2: Cache-Heavy (for repeated queries)
─────────────────────────────────────────────────
Query → semantic cache lookup → hit? Return cached answer (2ms)
                                 miss? Run full pipeline → cache result

Cache hit rate: 15–40% for typical enterprise Q&A systems

PATTERN 3: Tiered Routing (for mixed query types)
─────────────────────────────────────────────────
Query complexity classifier:
  → simple (60%) → BM25 only → small LLM (100ms total)
  → complex (40%) → hybrid + reranking → large LLM (1s total)
```
