### Token Cost Deep Dive

Understanding token costs helps you design efficient projects. The key insight: files loaded conditionally cost **zero** until triggered.

```
Init cost categories:
═══════════════════════════════════════════════════════════════

ALWAYS-LOADED (pay every session):
  Enterprise CLAUDE.md   variable  — keep under 2,000 tokens
  User CLAUDE.md         variable  — keep under 2,000 tokens
  Project CLAUDE.md      variable  — keep under 4,000 tokens
  CLAUDE.local.md        variable  — keep under 2,000 tokens
  Auto-Memory MEMORY.md  up to 25KB (~6,250 tokens max)

MCP (pay per connected server, every session):
  Each MCP server        ~2,650 tokens fixed overhead
  5 servers = ~13,250 tokens fixed cost

NOT IN CONTEXT (0 tokens in context window):
  settings.json files    0 — parsed as config, not context
  keybindings.json       0 — UI config only
  MDM/registry/managed   0 — system config only

DEFERRED (0 until triggered):
  Rules (.claude/rules/) 0 → ~300-800 on first matching file read
  Skills                 0 → ~500-2,000 on /invocation
  Commands               0 → ~200-500 on /cmd
  Agents (subagent defs) 0 → loaded into subagent context, not parent
  Output styles          0 → ~200-500 on /config select
  Themes                 0 → applied visually, not in context
═══════════════════════════════════════════════════════════════
```

### Frontmatter Schema by File Type

```markdown
<!-- Rules file (.claude/rules/example.md) -->
---
paths:
  - src/api/**/*.ts
  - tests/api/**
priority: normal      # low | normal | high | critical
description: "Brief description for /rules list command"
---
Rule content here...


<!-- Skill file (.claude/skills/my-skill/SKILL.md) -->
---
name: my-skill
description: "One-line description shown in /skills list"
tools:
  - Read
  - Edit
  - Bash
maxTurns: 30
temperature: 0.2
---
Skill instructions here...


<!-- Subagent file (.claude/agents/my-agent.md) -->
---
name: my-agent
description: "Shown in /agents list"
model: claude-sonnet-4-6
tools:
  - Read
  - Grep
  - Bash
allowedPaths:
  - src/**
  - tests/**
maxTurns: 20
memory: isolated      # isolated | shared | none
temperature: 0.3
---
Agent system prompt here...


<!-- Command file (.claude/commands/my-cmd.md) -->
---
name: my-cmd
description: "Shown in /help and command picker"
args:
  - name: target
    description: "File or directory to process"
    required: true
---
Command template: Process {{target}} by doing...
```

### Decision Guide: Which File Type to Use?

```
I need to give Claude permanent instructions that apply everywhere
  └─ User CLAUDE.md (~/.claude/CLAUDE.md)

I need to give Claude project context for my whole team
  └─ Project CLAUDE.md (CLAUDE.md in root) — commit to git

I need personal project context that shouldn't be in git
  └─ CLAUDE.local.md — add to .gitignore

I need instructions that only apply to specific file types or directories
  └─ .claude/rules/*.md with paths: frontmatter — MOST EFFICIENT

I need a repeatable multi-step capability (like "review PR" or "deploy")
  └─ .claude/skills/<name>/SKILL.md

I need to spawn a specialist agent for parallel/isolated work
  └─ .claude/agents/<name>.md

I need a quick shortcut command (/deploy, /review, /test)
  └─ .claude/commands/<name>.md

I need facts to persist across sessions and survive compaction
  └─ MEMORY.md (auto-managed via /memory add)

I need to connect an external tool/database/API to Claude
  └─ .mcp.json + MCP server implementation

I need to control what Claude is allowed to do (permissions/model)
  └─ .claude/settings.json (team) or .claude/settings.local.json (personal)

I need to bundle multiple components for distribution
  └─ Plugin with plugin.json manifest
```

| Commands .md | Unlimited | 500 tokens (~40 lines) | Per invocation |
