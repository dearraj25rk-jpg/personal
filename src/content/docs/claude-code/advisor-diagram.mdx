## /advisor Quick Reference

### What /advisor Does

```
Normal session (default):
  ┌──────────────────────────────────┐
  │  claude-sonnet-4-6 (executor)    │
  │  Does everything itself          │
  └──────────────────────────────────┘

/advisor activated:
  ┌──────────────────────────────────┐
  │  claude-sonnet-4-6 (executor)    │  ← you talk to this
  │  Writes code, runs tools         │
  │            │                     │
  │            │ Context snapshot    │
  │            ▼                     │
  │  claude-opus-4-7 (advisor)       │  ← reviews periodically
  │  Provides strategic guidance     │
  └──────────────────────────────────┘
```

### When Advisor Fires

| Trigger | Condition |
|---------|----------|
| Turn-count | Every N turns (configurable) |
| Complexity threshold | When executor signals uncertainty |
| Manual | `/advisor now` forces immediate consultation |
| Checkpoint | After major file changes |

### Cost Comparison

| Mode | Cost per 1000-turn session | Quality |
|------|--------------------------|---------|
| Sonnet only | ~$5–15 | Good |
| /advisor (Sonnet + Opus reviews) | ~$20–45 | Better for complex tasks |
| Opus only | ~$50–150 | Best, slowest |

### Activating /advisor

```bash
# In a Claude Code session
/advisor                    # Toggle on/off
/advisor --frequency 5      # Advisor every 5 turns
/advisor --model opus-4-7   # Use specific Opus model
/advisor now                # Force immediate consultation
```

### /advisor Session Flow Detail

```
Session with /advisor enabled:

Turn 1–N (executor phase):
  You → Sonnet 4.6 → tool calls, edits, analysis
                    │
                    │ Every N turns (or complexity signal)
                    ▼
              Context snapshot taken
              [conversation so far + current state]
                    │
                    ▼
              Opus 4.7 receives snapshot
              Opus 4.7 generates strategic review:
                - "The current approach will hit X problem"
                - "Consider Y alternative for the auth refactor"
                - "Missing error handling on Z path"
                    │
                    ▼
              Sonnet 4.6 receives Opus guidance
              Sonnet 4.6 adjusts plan accordingly
                    │
                    ▼
Turn N+1 onwards: Sonnet continues with improved direction
```

### When /advisor Provides the Most Value

| Task type | /advisor benefit | Worth the cost? |
|-----------|-----------------|----------------|
| Large refactors (1000+ lines) | Catches architectural mistakes early | Yes |
| Security audit | Opus identifies subtle vulnerabilities | Yes |
| Greenfield design | Strategic direction at key checkpoints | Yes |
| Bug fix (< 50 lines) | Minimal benefit — Sonnet handles it | No |
| Formatting / docs | No benefit | No |
| Simple CRUD feature | Low benefit | Usually not |

### /advisor vs Full Opus Session

```
Task: Refactor authentication module (500 lines)

Option A: Sonnet only (default)
  Cost: ~$1.50-$3.00
  Risk: May take suboptimal approach on complex decisions

Option B: /advisor (Sonnet executor + Opus reviews at turns 5, 10, 15)
  Cost: ~$4.00-$8.00 (Opus reviews = ~$2-4 extra)
  Benefit: Opus strategic guidance reduces backtracking

Option C: Opus 4.7 only
  Cost: ~$15-$30
  Benefit: Every decision gets Opus reasoning

Decision rule:
  If task complexity > medium AND mistakes are costly → use /advisor
  If task complexity > high AND no cost constraint → use Opus directly
  Otherwise → Sonnet is sufficient
```

## /advisor Reference

### Dual-Model Architecture — Full Flow

```
┌─────────────────────────────────────────────────────────────────────┐
│                      /advisor SESSION                               │
│                                                                     │
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │                  SONNET 4.6 (executor)                        │  │
│  │                                                               │  │
│  │  Turn 1 ──► tool calls, edits, bash commands, analysis        │  │
│  │  Turn 2 ──► reads files, writes code, runs tests              │  │
│  │  Turn 3 ──► refactors, debugs, explores                       │  │
│  │  Turn N ──► [complexity threshold OR turn-count hit]          │  │
│  │             │                                                 │  │
│  └─────────────┼─────────────────────────────────────────────────┘  │
│                │  Context snapshot                                   │
│                │  [full conversation + tool results + current state] │
│                ▼                                                     │
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │                  OPUS 4.7 (advisor)                           │  │
│  │                                                               │  │
│  │  Receives: everything Sonnet has seen so far                  │  │
│  │  Evaluates: architectural soundness, missed edge cases,       │  │
│  │             security implications, better patterns            │  │
│  │  Produces: strategic guidance (NOT direct code changes)       │  │
│  └───────────────────────────────────────────────────────────────┘  │
│                │  Opus guidance returned to Sonnet                  │
│                ▼                                                     │
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │                  SONNET 4.6 (executor, cont.)                 │  │
│  │                                                               │  │
│  │  Turn N+1 ──► adjusts plan based on Opus guidance            │  │
│  │  Turn N+2 ──► continues implementation, improved direction   │  │
│  │  ...                                                          │  │
│  │  Turn 2N  ──► [next advisor checkpoint]                       │  │
│  └───────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  Key points:                                                         │
│  • Sonnet does ALL tool execution — Opus never runs tools directly  │
│  • Opus sees full context snapshot — no information loss            │
│  • Advisor fires at checkpoints — not on every turn                 │
│  • You always interact with Sonnet — Opus is invisible              │
└─────────────────────────────────────────────────────────────────────┘
```

### Trigger Conditions — When Advisor Fires

The advisor model fires at one of four trigger conditions, whichever comes first:

| Trigger | Why advisor fires | Example scenario |
|---------|------------------|-----------------|
| **Ambiguous requirements** | Multiple valid interpretations exist and the executor signals uncertainty | "Make authentication better" — Sonnet flags that this could mean security hardening, UX improvement, or OAuth integration |
| **Architectural decisions** | A pattern or structural choice will have long-term impact | "Should I use event sourcing for the order system?" — Opus evaluates trade-offs across the full codebase context |
| **Trade-off analysis** | Competing concerns with no clear winner | "Performance vs maintainability?" — Opus reasons about the specific constraints (team size, SLA, tech debt) visible in the snapshot |
| **Complex debugging** | Multiple hypotheses have been exhausted without resolution | Heisenbug in concurrent code — Opus applies fresh reasoning across all the debug attempts Sonnet has accumulated |
| **Novel algorithm design** | No established patterns apply; first-principles reasoning needed | "Optimize this graph traversal for our specific data distribution" — Opus designs from scratch given the constraints |
| **Turn-count checkpoint** | Periodic review at configured interval (default: every 10 turns) | Routine check-in even when no explicit trigger has fired |
| **Manual force** | User runs `/advisor now` | You suspect the approach is off-track and want Opus input immediately |

> **How Sonnet signals uncertainty:** When the executor model hits a decision point it is not confident about, it emits an internal complexity signal. This is model-generated, not rule-based — the threshold cannot be tuned directly, but the `--frequency` flag controls the turn-count fallback.

### Token Cost Comparison

Costs are estimates for a representative 100-turn coding session on a medium-complexity feature (~500 lines touched).

| Mode | Executor model | Advisor model | Approx. input tokens | Approx. cost | Quality ceiling |
|------|---------------|--------------|---------------------|--------------|----------------|
| **Sonnet only** (default) | Sonnet 4.6 ($3/M) | None | ~200K | ~$0.60 | Good — handles most daily work |
| **Haiku only** (cheapest) | Haiku 4.5 ($0.80/M) | None | ~200K | ~$0.16 | Limited — simple tasks only |
| **/advisor** (Sonnet + Opus reviews) | Sonnet 4.6 ($3/M) | Opus 4.7 ($15/M) | ~200K + ~30K per review | ~$1.50–4.00 | Better — Opus strategic guidance without Opus per-turn cost |
| **Opus 4.7 only** | Opus 4.7 ($15/M) | None | ~200K | ~$3.00 | Best reasoning every turn |
| **Opus 4.8 only** (newest) | Opus 4.8 ($15/M) | None | ~200K | ~$3.00 | Frontier — most capable |

> **Why /advisor is cost-efficient:** A full Opus session charges $15/M on every single turn. With /advisor, you pay Opus rates only on advisor snapshots (typically 3–6 per long session), while paying Sonnet rates for all execution turns. The advisor snapshots include compressed context, not raw full-length conversation, further reducing Opus token consumption.

### /advisor vs Full Opus — Decision Guide

Use this decision tree to pick the right mode for your task:

```
Is this task longer than ~30 turns OR touches architecture?
│
├─ NO  ──► Use Sonnet (default). /advisor overhead not worth it.
│
└─ YES
    │
    Is correctness of every decision critical (security audit,
    irreversible production deploy, novel algorithm)?
    │
    ├─ YES ──► Use Opus directly (full Opus session)
    │          Every turn gets Opus reasoning. Worth the 5× cost.
    │
    └─ NO
        │
        Does the task have clear checkpoints where strategic
        review would catch mistakes early (refactor, greenfield)?
        │
        ├─ YES ──► Use /advisor
        │          Sonnet executes, Opus reviews at key moments.
        │          Best quality-to-cost ratio for long tasks.
        │
        └─ NO  ──► Use Sonnet (default)
                   The task is probably well-defined enough that
                   Sonnet handles it without strategic oversight.
```

**Summary table:**

| Scenario | Recommended | Reason |
|----------|------------|--------|
| Simple bug fix (< 50 lines) | Sonnet only | Over-engineered with advisor |
| Standard feature (50–500 lines) | Sonnet only | Sonnet is capable; advisor overhead not justified |
| Large refactor (500+ lines) | /advisor | Catches architectural drift mid-task |
| Security audit | Opus directly | Every decision needs Opus judgment |
| Greenfield system design | /advisor | Periodic strategic review at key decisions |
| Concurrency debugging | /advisor or Opus | Complex enough to benefit from Opus reasoning |
| Formatting / docs / bulk ops | Haiku | Cheapest; no reasoning required |

### Configuring /advisor

#### Toggle and frequency (in-session)

```bash
# Inside a Claude Code session:
/advisor                     # Toggle on (uses default frequency = every 10 turns)
/advisor --frequency 5       # Advisor every 5 turns
/advisor --frequency 20      # Advisor every 20 turns (less frequent = cheaper)
/advisor --model opus-4-8    # Use Opus 4.8 as advisor instead of Opus 4.7
/advisor now                 # Force an immediate advisor consultation
/advisor off                 # Disable advisor for the rest of this session
```

#### Persistent configuration via settings.json

Set advisor behavior for all sessions in a project:

```json
// .claude/settings.json
{
  "advisor": {
    "enabled": true,
    "model": "claude-opus-4-7",
    "frequency": 10,
    "triggerOnComplexity": true
  }
}
```

#### Configuration via /config

```bash
# Open interactive config UI
/config

# Navigate to: AI Settings → Advisor → Enable
# Set frequency and model from the dropdown menus
```

Available advisor model options (as of v2.1.126):
- `claude-opus-4-8` — newest Opus, highest capability
- `claude-opus-4-7` — default advisor model, 1M context
- `claude-opus-4-6` — 1M context, stable option

> **Note:** The advisor model must be an Opus model. Setting `--model` to Sonnet or Haiku for the advisor is not supported — the feature is designed around the Sonnet-executes / Opus-advises split.

### Understanding the Context Snapshot

When the advisor fires, Sonnet does not pass the raw conversation verbatim. It constructs a context snapshot:

```
Advisor snapshot contents:
┌──────────────────────────────────────────────────────┐
│  1. Original task description / user goal            │
│  2. Key decisions made so far (summarised)           │
│  3. Current file state (relevant files only)         │
│  4. Last N tool results (writes, test outputs, etc.) │
│  5. Explicit question for Opus (why it's consulting) │
└──────────────────────────────────────────────────────┘
```

This snapshot is optimised to fit within Opus context limits while preserving the information Opus needs for strategic guidance. Token compression is automatic — you do not need to manage it.

## Advisor Model as of June 2026

The `/advisor` command invokes a dual-model session:
- **Executor**: `claude-sonnet-4-6` — handles all tool calls and active work
- **Advisor**: `claude-opus-4-8` — reviews intermediate steps and provides guidance

Since `claude-opus-4-8` took the `opus` alias in v2.1.126, the advisor automatically uses the newest Opus model. Prior documentation referenced Opus 4.7 as the advisor model — this is now outdated. The advisor always uses whatever model the `opus` alias resolves to.

## /advisor vs Full-Opus Session — Break-Even Analysis

The economic case for `/advisor` is that Sonnet handles 90%+ of the work at 5× lower cost, while Opus only reviews key decision points. Here is a concrete break-even calculation:

```
Scenario: 50-turn refactoring session
Input tokens per turn: ~3,000 (prompt + context)
Output tokens per turn: ~800 (response + tool calls)
Advisor activations: ~5 times (one per major decision point)

Full-Opus session cost:
  50 × (3,000 × $15/M + 800 × $75/M) = 50 × (0.045 + 0.060) = $5.25

/advisor session cost:
  45 Sonnet turns × (3,000 × $3/M + 800 × $15/M) = 45 × (0.009 + 0.012) = $0.95
  5 Opus review turns × (5,000 × $15/M + 1,500 × $75/M) = 5 × (0.075 + 0.113) = $0.94
  Total: $1.89

Savings: $5.25 - $1.89 = $3.36 (64% cheaper) for same quality on most of the session
```

**When full-Opus beats /advisor:** If your session is Opus-heavy (mostly complex reasoning turns, very few routine tool calls), or if you need the advisor model's judgment on every single step (security audits, novel algorithm work), the overhead of advisor context transfer can make full-Opus sessions more efficient.

**Rule of thumb:** Use `/advisor` for development sessions mixing routine work with occasional hard problems. Use full-Opus directly when every single turn requires frontier reasoning.
