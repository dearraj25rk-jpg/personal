## MCP Quick Reference

### Architecture Layers

```
┌─────────────────────────────────────────┐
│              MCP HOST                   │
│   (Claude Code, Claude Desktop, IDEs)   │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │          MCP CLIENT             │   │
│   │  (one client per server)        │   │
│   └──────────────┬──────────────────┘   │
└──────────────────┼──────────────────────┘
                   │ JSON-RPC 2.0
   ┌───────────────▼──────────────────────┐
   │           MCP SERVER                 │
   │  Tools | Resources | Prompts         │
   │  (your database, API, filesystem)    │
   └──────────────────────────────────────┘
```

### Three Primitives

| Primitive | Claude can | Analogy | Example |
|-----------|-----------|---------|---------|
| **Tools** | Call (execute actions) | Function call | `query_database`, `send_email` |
| **Resources** | Read (get data) | File/URL | `file://project/schema.sql` |
| **Prompts** | Use (preset templates) | Snippet | `code-review`, `summarize-pr` |

### Transport Types

| Transport | Status | When to use |
|-----------|--------|------------|
| `stdio` | **Recommended** | Local servers — simple, secure |
| `http` (Streamable) | Current | Remote/cloud servers |
| `sse` | **Deprecated** | Legacy only |

### Configuration Scopes

| Scope | File | Who it applies to |
|-------|------|------------------|
| Project | `.mcp.json` (root) | Anyone on the project |
| User | `~/.claude/.mcp.json` | You, across all projects |
| Local | `.claude/.mcp.json.local` | You, this project only |
| Enterprise | Managed config | All org users |

### JSON-RPC 2.0 Message Flow

```
Claude Code (Client)                    MCP Server
        │                                    │
        │── initialize ────────────────────► │  Protocol handshake
        │◄── initialized ──────────────────── │
        │                                    │
        │── tools/list ───────────────────► │  Discover available tools
        │◄── {tools: [...]} ──────────────── │
        │                                    │
        │── tools/call ───────────────────► │  Claude calls a tool
        │   {name:"query_db", args:{...}}    │
        │◄── {content:[{type:"text",...}]} ── │  Tool result returned
        │                                    │
        │── resources/list ───────────────► │  (Optional) resource discovery
        │── prompts/list ──────────────────► │  (Optional) prompt discovery
```

### Building a Custom MCP Server (TypeScript minimal)

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "my-server", version: "1.0.0" });

server.tool("query_orders", {
  order_id: z.string().describe("The order ID to look up")
}, async ({ order_id }) => {
  const result = await db.query("SELECT * FROM orders WHERE id = $1", [order_id]);
  return { content: [{ type: "text", text: JSON.stringify(result.rows[0]) }] };
});

const transport = new StdioServerTransport();
await server.connect(transport);
```

### Tool Description Best Practices

Good tool descriptions reduce Claude's token usage and improve accuracy:

| Pattern | Example |
|---------|---------|
| Action verb + noun | `"Get customer order history by customer ID"` |
| Include constraints | `"Max 100 results. Returns null if not found."` |
| Mention side effects | `"WRITES to database. Irreversible."` |
| Expected input format | `"Date in ISO 8601 format: YYYY-MM-DD"` |

**Keep descriptions under 100 tokens** — each tool schema costs tokens. A server with 20 tools costs ~2,650 tokens regardless of description length.

### Security Checklist for MCP Servers

- [ ] Validate all inputs with a schema library (Zod, Pydantic)
- [ ] Never expose destructive operations (DROP TABLE) without confirmation
- [ ] Use `readonly: true` flag for read-only tools to signal intent
- [ ] Scope database users to minimum required permissions
- [ ] Audit log all MCP tool calls via PostMCPTool hook
- [ ] Use `CLAUDE_CODE_DISABLE_MCP_TOOLS` to blocklist dangerous tools
- [ ] Rotate credentials; use environment variables never hardcoded in `.mcp.json`

## MCP Protocol Deep Dive

### JSON-RPC 2.0 Message Format

MCP uses JSON-RPC 2.0 as its wire format. All messages are newline-delimited JSON objects sent over the chosen transport. There are four message types: **requests**, **responses**, **notifications**, and **errors**.

**Request** (client → server, expects a response):

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "query_database",
    "arguments": {
      "sql": "SELECT * FROM users WHERE active = true LIMIT 10",
      "database": "production"
    }
  }
}
```

**Response** (server → client, matched by `id`):

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "[{\"id\":1,\"email\":\"alice@example.com\"},{\"id\":2,\"email\":\"bob@example.com\"}]"
      }
    ],
    "isError": false
  }
}
```

**Notification** (server → client, no response expected — used for progress):

```json
{
  "jsonrpc": "2.0",
  "method": "notifications/tools/progress",
  "params": {
    "progressToken": "tok_abc123",
    "progress": 42,
    "total": 100,
    "message": "Processing row 42 of 100..."
  }
}
```

**Error Response** (server → client, something went wrong):

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32602,
    "message": "Invalid params",
    "data": {
      "field": "sql",
      "reason": "SQL injection pattern detected in query"
    }
  }
}
```

**Standard JSON-RPC error codes:**

| Code | Name | Meaning |
|------|------|---------|
| `-32700` | Parse error | Invalid JSON received |
| `-32600` | Invalid request | Not a valid Request object |
| `-32601` | Method not found | Method does not exist |
| `-32602` | Invalid params | Invalid method parameters |
| `-32603` | Internal error | Internal JSON-RPC error |
| `-32000` to `-32099` | Server error | Reserved for MCP server errors |

### Capability Negotiation Sequence

The MCP initialize handshake lets client and server agree on supported features before any tool calls happen:

```
Client                                       Server
  │                                             │
  │──── initialize ────────────────────────────►│
  │     {                                       │
  │       "jsonrpc": "2.0",                     │
  │       "id": 0,                              │
  │       "method": "initialize",               │
  │       "params": {                           │
  │         "protocolVersion": "2024-11-05",    │
  │         "capabilities": {                   │
  │           "roots": {"listChanged": true},   │
  │           "sampling": {}                    │
  │         },                                  │
  │         "clientInfo": {                     │
  │           "name": "claude-code",            │
  │           "version": "2.1.126"              │
  │         }                                   │
  │       }                                     │
  │     }                                       │
  │                                             │
  │◄─── result ────────────────────────────────│
  │     {                                       │
  │       "protocolVersion": "2024-11-05",      │
  │       "capabilities": {                     │
  │         "tools": {"listChanged": true},     │
  │         "resources": {"subscribe": true},   │
  │         "prompts": {"listChanged": false},  │
  │         "logging": {}                       │
  │       },                                    │
  │       "serverInfo": {                       │
  │         "name": "my-db-server",             │
  │         "version": "1.2.0"                  │
  │       }                                     │
  │     }                                       │
  │                                             │
  │──── notifications/initialized ─────────────►│
  │     (client signals ready — no response)    │
  │                                             │
  │──── tools/list ────────────────────────────►│
  │◄─── result: [{name, description, schema}]  │
  │                                             │
  │     ... normal operation begins ...         │
```

**Key capability flags:**

| Capability | What it enables |
|-----------|----------------|
| `tools.listChanged` | Server can send `notifications/tools/list_changed` when tools update |
| `resources.subscribe` | Client can subscribe to resource change notifications |
| `sampling` | Server can request LLM completions from the client (advanced) |
| `roots.listChanged` | Client exposes workspace roots (filesystem boundaries) |
| `logging` | Server can send structured log messages to the client |

## Transport Comparison

### stdio vs HTTP — When to Use Each

```
stdio transport:                    HTTP (Streamable) transport:
────────────────                    ──────────────────────────────
Local process spawned by host       Remote service — any host, any port
Same machine only                   Any network-accessible endpoint
Pipe: stdin/stdout                  HTTP POST + SSE response stream
Process lifecycle = server lifetime Server runs independently
~0ms overhead per message           Network latency per request
No auth needed (process boundary)   Auth via headers (Bearer, API keys)
```

**Decision guide:**

| Scenario | Transport | Reason |
|----------|-----------|--------|
| Local CLI tool wrapping your database | `stdio` | Simple, no network exposure |
| Shared team server running in Kubernetes | `http` | Central, accessible to all devs |
| Sandboxed tool in CI environment | `stdio` | Process isolation, no open ports |
| SaaS MCP provider (e.g. Browserbase) | `http` | External network required |
| Dev-only personal scripts | `stdio` | Zero configuration |
| Multi-tenant enterprise deployment | `http` | One server → many users |

### Latency Characteristics

```
stdio (local):
  Spawn overhead (first call):   ~80–200ms  (process startup)
  Per-call overhead:             ~0–2ms     (IPC, negligible)
  Total for 100 tool calls:      ~200ms + (100 × 1ms) = ~300ms

http (local, loopback):
  Connection establishment:      ~5–10ms    (TCP + HTTP overhead)
  Per-call overhead:             ~3–8ms     (HTTP framing)
  Total for 100 tool calls:      ~10ms + (100 × 5ms) = ~510ms

http (remote, typical cloud):
  Connection establishment:      ~50–200ms  (TLS + network)
  Per-call overhead:             ~20–150ms  (network RTT)
  Total for 100 tool calls:      ~200ms + (100 × 80ms) = ~8,200ms
```

**Rule of thumb:** For interactive Claude Code sessions, keep round-trip tool calls under 500ms. Remote HTTP servers with high latency will noticeably slow down sessions.

### Configuration Differences

**stdio server configuration:**

```json
{
  "mcpServers": {
    "my-local-db": {
      "type": "stdio",
      "command": "node",
      "args": ["/absolute/path/to/server/index.js", "--port", "5432"],
      "env": {
        "DATABASE_URL": "${DATABASE_URL}",
        "NODE_ENV": "production"
      },
      "cwd": "/path/to/server/directory"
    }
  }
}
```

**HTTP server configuration:**

```json
{
  "mcpServers": {
    "remote-api": {
      "type": "http",
      "url": "https://mcp.internal.company.com/v1",
      "headers": {
        "Authorization": "Bearer ${MCP_API_TOKEN}",
        "X-Tenant-ID": "engineering"
      },
      "timeout": 30000
    }
  }
}
```

### Authentication Options

| Method | Transport | Configuration |
|--------|-----------|--------------|
| None (process boundary) | `stdio` | No auth config needed — OS user boundary |
| Bearer token | `http` | `"headers": {"Authorization": "Bearer ${TOKEN}"}` |
| API key header | `http` | `"headers": {"X-API-Key": "${API_KEY}"}` |
| mTLS (client certificates) | `http` | Configured at HTTP client level via env |
| OAuth 2.0 | `http` | Exchange token externally, pass as Bearer |
| AWS SigV4 | `http` | Use AWS SDK wrapper to sign requests |

**Environment variable substitution:** In `.mcp.json` files, `${VAR_NAME}` is substituted from the host process environment at load time. Never hardcode secrets directly in `.mcp.json`.

## Building Your Own MCP Server

### Full TypeScript Quick Start Template

Complete working server with tools, resources, and error handling. Install and run in under 5 minutes.

**1. Initialize project:**

```bash
mkdir my-mcp-server && cd my-mcp-server
npm init -y
npm install @modelcontextprotocol/sdk zod
npm install -D typescript @types/node tsx
npx tsc --init --target ES2022 --module NodeNext --moduleResolution NodeNext
```

**2. Create `src/index.ts`:**

```typescript
import { McpServer, ResourceTemplate } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

// ── Server setup ─────────────────────────────────────────────────────────────
const server = new McpServer({
  name: "my-mcp-server",
  version: "1.0.0",
});

// ── Tool: query orders ────────────────────────────────────────────────────────
server.tool(
  "get_order",
  "Get order details by order ID. Returns null if not found.",
  {
    order_id: z.string().regex(/^ORD-\d+$/).describe("Order ID in format ORD-12345"),
  },
  async ({ order_id }) => {
    try {
      // Replace with real database call
      const order = await fakeDb.getOrder(order_id);
      if (!order) {
        return {
          content: [{ type: "text", text: `Order ${order_id} not found.` }],
          isError: false,
        };
      }
      return {
        content: [{ type: "text", text: JSON.stringify(order, null, 2) }],
      };
    } catch (err) {
      return {
        content: [{ type: "text", text: `Database error: ${(err as Error).message}` }],
        isError: true,
      };
    }
  }
);

// ── Tool: list recent orders ──────────────────────────────────────────────────
server.tool(
  "list_recent_orders",
  "List the N most recent orders. Max 50.",
  {
    limit: z.number().int().min(1).max(50).default(10).describe("Number of orders to return"),
    status: z.enum(["all", "pending", "shipped", "delivered"]).default("all"),
  },
  async ({ limit, status }) => {
    const orders = await fakeDb.listOrders({ limit, status });
    return {
      content: [
        { type: "text", text: `Found ${orders.length} orders:\n${JSON.stringify(orders, null, 2)}` },
      ],
    };
  }
);

// ── Resource: order schema ────────────────────────────────────────────────────
server.resource(
  "order-schema",
  "schema://orders",
  { mimeType: "application/json" },
  async () => ({
    contents: [{
      uri: "schema://orders",
      mimeType: "application/json",
      text: JSON.stringify({
        type: "object",
        properties: {
          id: { type: "string" },
          customer_email: { type: "string" },
          status: { type: "string", enum: ["pending", "shipped", "delivered"] },
          total_usd: { type: "number" },
          created_at: { type: "string", format: "date-time" },
        },
      }, null, 2),
    }],
  })
);

// ── Prompt: order summary template ───────────────────────────────────────────
server.prompt(
  "summarize-order",
  "Generate a customer-facing order summary",
  { order_id: z.string() },
  ({ order_id }) => ({
    messages: [{
      role: "user",
      content: {
        type: "text",
        text: `Use the get_order tool to fetch order ${order_id}, then write a friendly customer-facing summary email. Include: status, items, estimated delivery.`,
      },
    }],
  })
);

// ── Start server ──────────────────────────────────────────────────────────────
const transport = new StdioServerTransport();
await server.connect(transport);
console.error("my-mcp-server running on stdio"); // stderr only — stdout is protocol

// ── Fake DB (replace with real implementation) ────────────────────────────────
const fakeDb = {
  async getOrder(id: string) {
    if (id === "ORD-12345") {
      return { id, customer_email: "alice@example.com", status: "shipped", total_usd: 99.99 };
    }
    return null;
  },
  async listOrders({ limit, status }: { limit: number; status: string }) {
    return [{ id: "ORD-12345", status: "shipped", total_usd: 99.99 }].slice(0, limit);
  },
};
```

**4. Register in `.mcp.json`:**

**Development tips:**

- Write all debug output to **stderr** — stdout is the JSON-RPC protocol channel
- Use Zod schemas for every input — they become the tool's JSON Schema automatically
- Keep each tool focused on one action — Claude picks tools better with narrow descriptions
- Return `isError: true` for expected failures (not found) vs throwing for unexpected errors
