### Model Selection Rule of Thumb

```
Task complexity  →  Recommended model
──────────────────────────────────────
Formatting / bulk ops → Haiku 4.5 (10-20× cheaper than Opus)
Standard feature work → Sonnet 4.6 (default, best balance)
Complex debugging     → Opus 4.7  (1M ctx, strong reasoning)
Hardest problems      → Opus 4.8  (newest, most capable Opus)
```

### Effort Levels

Effort levels control how much "thinking" Claude does before responding. They map to extended thinking budgets:

| Level | Extended Thinking | Best for | Cost multiplier |
|-------|------------------|---------|----------------|
| `low` | None | Simple edits, formatting | 1× base |
| `normal` | Minimal | Standard feature work | ~1.3× |
| `high` | Substantial | Complex features, debugging | ~2× |
| `xhigh` | Maximum | Architecture, hardest problems | ~4× |

> **Opus 4.8 default effort:** Opus 4.8 defaults to `normal` effort. Use `xhigh` explicitly for maximum reasoning. Opus 4.7 defaults to `xhigh` for requests that trigger extended thinking.

### Fast Mode (`/fast`)

**Fast Mode** is an Opus-specific feature that delivers faster output without downgrading to a smaller model:

```
Normal Opus session:          /fast session:
─────────────────────         ─────────────────────
Opus 4.8 reasoning           Opus 4.8 reasoning
Full deliberation            Optimized for speed
Slower token generation      Faster token generation
                             Same model capability
```

- **Toggle**: Type `/fast` in the REPL to enable/disable Fast Mode
- **Available for**: Opus 4.8, 4.7, 4.6 (not Sonnet or Haiku — they are already fast)
- **When to use**: When you want Opus reasoning power but response latency matters
- **Cost**: Same as the underlying Opus model — no surcharge for Fast Mode

```bash
# Start a session with Fast Mode
claude --model claude-opus-4-8

# Inside the session, toggle Fast Mode
> /fast

# Or start a session with both model + fast mode via config
# .claude/settings.json:
{
  "model": "claude-opus-4-8",
  "fastMode": true
}
```

### Switching Models

```bash
# CLI flag (before session starts)
claude --model claude-opus-4-8
claude --model claude-haiku-4-5

# Inside a running session
/model claude-opus-4-8
/model claude-sonnet-4-6

# Environment variable
export ANTHROPIC_MODEL=claude-opus-4-8
claude

# Aliases (shortest form)
claude --model opus     # → claude-opus-4-8
claude --model sonnet   # → claude-sonnet-4-6
claude --model haiku    # → claude-haiku-4-5
```

### /fast Mode — Opus Speed Optimisation

Fast Mode delivers faster output from Opus models without switching to a smaller, less capable model:

```
Standard Opus session:              /fast Opus session:
──────────────────────              ───────────────────
Opus 4.8                            Opus 4.8
Full deliberation before            Optimised token generation
each token batch                    Reduced inter-token latency
Slower responses                    Faster responses (~2–3× faster)
Deeper per-step reasoning           Same overall reasoning quality
                                    Same model weights
```

**When to use /fast:**

| Situation | Use /fast? | Why |
|-----------|-----------|-----|
| Interactive session (you are waiting) | Yes | Reduces perceived latency |
| Unattended overnight run | No | Speed doesn't matter; quality does |
| CI pipeline with time limit | Yes | Avoids timeout on long Opus tasks |
| Security audit requiring thoroughness | No | Prioritise deliberation over speed |
| Rapid prototyping with Opus | Yes | Good quality + responsive feel |

**Activating Fast Mode:**

```bash
# Toggle inside a session
> /fast
# Output: Fast Mode enabled — Opus 4.8 optimised for speed

# Start session with Fast Mode pre-enabled
# .claude/settings.json:
{
  "model": "claude-opus-4-8",
  "fastMode": true
}

# CLI: no direct --fast flag; use settings.json or /fast in session
```

> Fast Mode is available for Opus 4.8, 4.7, and 4.6. It is not applicable to Sonnet or Haiku — those models are already optimised for low latency. Cost is identical to the standard Opus rate.

### Real-World Cost Examples

Costs computed at standard pricing (no caching). Actual cost with prompt caching (reads at 0.1× input rate after first cache miss) is typically 40–70% lower for repeated sessions on the same codebase.

#### Example 1: Small bug fix

```
Task: Fix null-pointer exception in user service (20 lines changed)
Model: Sonnet 4.6

Estimated tokens:
  Input:  ~8,000  (prompt + context)
  Output: ~1,000  (fix + explanation)

Cost:
  Input:  8,000  × $3.00/1M  = $0.024
  Output: 1,000  × $15.00/1M = $0.015
  Total:  ~$0.04

Same task on Opus 4.8:
  Input:  8,000  × $15.00/1M = $0.12
  Output: 1,000  × $75.00/1M = $0.075
  Total:  ~$0.20  (5× more expensive, minimal quality gain)
```

#### Example 2: Feature implementation

```
Task: Add OAuth2 login (new route, middleware, tests — ~300 lines)
Model: Sonnet 4.6 (default)

Estimated tokens:
  Input:  ~60,000  (multi-turn, reading existing files)
  Output: ~15,000  (code + tests)

Cost:
  Input:  60,000  × $3.00/1M  = $0.18
  Output: 15,000  × $15.00/1M = $0.225
  Total:  ~$0.41

With prompt caching (files cached after first read):
  Cache:  45,000  × $0.30/1M  = $0.014  (reads same files multiple turns)
  New:    15,000  × $3.00/1M  = $0.045
  Output: 15,000  × $15.00/1M = $0.225
  Total:  ~$0.28  (32% cheaper with caching)
```

#### Example 3: Large refactor with /advisor

```
Task: Refactor authentication module (500 lines, 50-turn session)
Mode: /advisor (Sonnet executor + 5 Opus advisor checkpoints)

Sonnet execution (50 turns):
  Input:  ~200,000 tokens × $3.00/1M  = $0.60
  Output: ~50,000  tokens × $15.00/1M = $0.75

Opus advisor (5 × ~10K token snapshots):
  Input:  ~50,000  tokens × $15.00/1M = $0.75
  Output: ~10,000  tokens × $75.00/1M = $0.75

Total /advisor: ~$2.85

Comparison:
  Sonnet only:   ~$1.35  (cheaper, but may miss architectural issues)
  /advisor:      ~$2.85  (2× cost, strategic Opus guidance at checkpoints)
  Opus 4.7 only: ~$12.50 (9× cost, every turn gets Opus reasoning)
```

#### Example 4: Bulk CI/CD task

```
Task: Add copyright header to 200 TypeScript files
Model: Haiku 4.5

Estimated tokens per file:
  Input:  ~500 tokens (file content + instruction)
  Output: ~50  tokens (just the header line)

200 files total:
  Input:  100,000 × $0.80/1M  = $0.08
  Output: 10,000  × $4.00/1M  = $0.04
  Total:  ~$0.12

Same task on Sonnet: ~$0.50  (4× more, no quality benefit)
Same task on Opus:   ~$1.60  (13× more, no quality benefit)
```

## Choosing Between Opus 4.8 and Opus 4.7

Opus 4.8 and Opus 4.7 have identical pricing ($15/M input, $75/M output, $1.50/M cache) and the same 1M context window. Here is when to reach for each:

| Scenario | Use Opus 4.8 | Use Opus 4.7 |
|----------|-------------|--------------|
| You want the newest model | ✓ | — |
| You use the `opus` alias | ✓ (it resolves to 4.8) | ✗ (alias points to 4.8) |
| Pinning to a specific model ID in CI | `claude-opus-4-8` | `claude-opus-4-7` |
| Extended thinking (xhigh effort) | ✓ same | ✓ same |
| Architecture decisions | ✓ (slightly stronger) | ✓ fine |
| You need maximum capability on hardest problems | ✓ prefer 4.8 | Falls back fine |

**Rule of thumb:** Use `claude-opus-4-8` by default (it's newer and holds the `opus` alias). Use `claude-opus-4-7` only if you have a specific reason to pin to that version — for example, reproducing a result, testing a regression, or a team agreement to standardize on 4.7.

**Never use the `opus` alias in CI/CD.** The alias advances when new Opus models are released. Always pin to the full model ID (`claude-opus-4-8`) in pipeline definitions.

## Cache Write Pricing

In addition to cache read pricing (shown in the calculator above), Claude Code automatically writes prompt cache entries. Cache write pricing is separate from read pricing:

| Model | Cache Write (5-min TTL) | Cache Write (1-hr TTL) | Cache Read |
|-------|------------------------|------------------------|------------|
| Opus 4.8 / 4.7 / 4.6 | $3.75/M tokens | ~$30/M tokens | $1.50/M tokens |
| Sonnet 4.6 | $0.75/M tokens | ~$6/M tokens | $0.30/M tokens |
| Haiku 4.5 | $0.10/M tokens | ~$0.80/M tokens | $0.08/M tokens |

**Important:** Cache write costs are a one-time investment. You write once and read many times. A CLAUDE.md block that costs $0.75/M to write (Sonnet) costs only $0.30/M to read — you break even after 2.5 reads and save on every read after that.

**TTL selection:** Claude Code uses the 5-minute TTL for most caching. The 1-hour TTL is available via the API for stable content like system prompts that won't change across sessions.
