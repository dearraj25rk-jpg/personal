## Efficiency Quick Reference

### Cost Optimisation Decision Tree

```
Is the task simple (formatting, docs, small edits)?
  YES → Use Haiku 4.5 (cheapest)
  NO  ↓

Is it a frontier problem? (novel algorithm, complex architecture, critical system design)
  YES → Use Opus 4.8 (alias: opus) with effort=xhigh
  NO  ↓

Does it need deep reasoning (multi-file refactoring, complex debugging)?
  YES → Use Opus 4.7 with effort=high or xhigh
  NO  ↓

Standard feature work → Sonnet 4.6 (default, balanced)
```

### Effort Level Cost Impact

| Level | Extended Thinking | Relative cost | Use when |
|-------|-----------------|--------------|---------|
| `low` | None | ~0.5x | Simple, deterministic tasks |
| `normal` | Minimal | 1x (baseline) | Standard coding tasks |
| `high` | Substantial | ~2–3x | Complex bugs, architecture decisions |
| `xhigh` | Maximum | ~5–8x | Critical issues, complex refactors |

### Prompt Caching Economics

| Scenario | Cache hit rate | Cost savings |
|----------|--------------|-------------|
| Same CLAUDE.md, repeated tasks | 90%+ | ~75% off cached tokens |
| New session, warm cache | 60–80% | ~60% off |
| First run (cold cache) | 0% | Standard pricing |
| CI runs (same YAML) | 85–95% | ~75% off |

Cache read costs: **$0.30/M** vs $3.00/M input (Sonnet 4.6) → **10x cheaper**

### Output Style Cost Impact

| Style | Output length | Cost vs Default |
|-------|-------------|----------------|
| Default | Standard | 1x |
| Explanatory | ~40% longer | ~1.4x |
| Learning (tutor) | ~60% longer | ~1.6x |
| Custom (minimal) | ~50% shorter | ~0.5x |

### Context Engineering Checklist

Use this checklist before starting any substantial session to minimise waste and maximise cache hits:

**CLAUDE.md Health**
- [ ] Project CLAUDE.md is under 120 lines (aim for 80)
- [ ] No duplicate content across CLAUDE.md files in hierarchy
- [ ] No explanatory prose — only directives and facts
- [ ] Build/test commands are current and working
- [ ] Architecture section describes actual structure (not aspirational)

**Rules Setup**
- [ ] Domain-specific rules are in `.claude/rules/` with `paths:` globs, not in CLAUDE.md
- [ ] Rules are named alphabetically for load order control (01-security.md, 02-testing.md)
- [ ] Each rule file is focused on one concern
- [ ] Glob patterns are as specific as possible to avoid false loads

**Session Start**
- [ ] Session starts from the correct working directory (context sensitivity)
- [ ] Check `/context` to see current token baseline
- [ ] If continuing work, use `/resume <session-id>` not a fresh session
- [ ] Run `/compact focus on <area>` at ~65% context to control compaction summary

**Model & Effort Selection**
- [ ] Choose model based on task complexity (Haiku/Sonnet/Opus)
- [ ] Set effort level explicitly: `--effort low` for deterministic tasks
- [ ] For CI: use Sonnet + `--effort normal` + `--bare`
- [ ] For complex architecture: use Opus + `--effort high`

**Caching Strategy**
- [ ] CLAUDE.md content is stable (not changing every session — kills cache)
- [ ] System prompt block is above all user content in context order
- [ ] For CI: same CLAUDE.md across all PR jobs = shared cache = 75% savings
- [ ] Check cache hit rate: `claude --output-format json -p "." | jq .cache_hit_rate`

### Token Budget Guide by Task Type

| Task | Recommended model | Effort | Expected input tokens | Expected output tokens |
|------|-----------------|--------|---------------------|----------------------|
| Format/lint fix | Haiku 4.5 | low | 2K–5K | 200–500 |
| Single bug fix | Sonnet 4.6 | normal | 5K–20K | 500–2K |
| Feature addition | Sonnet 4.6 | normal | 10K–50K | 2K–10K |
| Security audit | Opus 4.7 | high | 20K–100K | 2K–8K |
| Architecture design | **Opus 4.8** | xhigh | 30K–80K | 5K–20K |
| Full codebase refactor | **Opus 4.8** + /advisor | high | 100K–500K | 20K–100K |
| CI PR review | Sonnet 4.6 | normal | 5K–30K | 1K–5K |

### Session Rhythm Best Practices

```
OPTIMAL SESSION RHYTHM (50-turn example):

Turns 1-10:   Exploration (Read, Grep, Glob) — gather context
               → Context at ~15-20%

Turns 11-25:  Core work (Edit, Write, Bash) — implement changes
               → Context at ~35-50%

Turn ~30:      Manual /compact focus on <work done>
               → Context back to ~20%, summary preserves progress

Turns 31-45:  Continued work + testing
               → Context at ~40-55%

Turn ~50:      /compact again if needed OR /todos + wrap up
               → Save key decisions to MEMORY.md before closing
```
